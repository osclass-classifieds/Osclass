# Osclass

Osclass is a self-hosted PHP script for running a classifieds or marketplace
website — listings, categories, locations, custom fields, user accounts,
comments, and a full backoffice to moderate and configure all of it. It's
old enough to have outlived the company that started it, and that's actually
part of the story worth knowing before you install it.

**This is a read-only source mirror.** It does not accept external pull
requests or issue reports. For downloads, documentation, and support, see
[osclass-classifieds.com](https://osclass-classifieds.com).

## A quick note on where this project has been

Osclass launched in 2010. In 2019, the original company behind it shut
down — the changelog entry for 3.9.0 literally reads "First release after
official Osclass Shutdown." The project didn't die with the company: it was
picked up and has been maintained continuously since, with 4.0.0 in
September 2020 marking the first release under new stewardship. If you've
ever wondered why the version number jumps from 4.5 straight to 8.0.0 —
that renumbering was deliberate, done specifically to avoid collisions and
confusion with other forks that spun off around the same time.

Since then it's had a steady release cadence rather than a burst-and-abandon
one: security and compatibility fixes for every PHP major version as it's
released (7.2 through 8.5, most recently in 8.3.1 / January 2026), plus
larger structural work along the way — a rewritten cookie/session layer,
utf8mb4/emoji support, configurable custom search-URL rules, and ongoing
query-count optimization as MySQL/PHP itself has evolved.

## Requirements

- PHP 7.2–8.5
- MySQL 5.7+ or MariaDB
- PHP extensions: MySQLi, GD, cURL
- ImageMagick — optional, better image quality than GD alone

Install is a five-minute web installer: upload the files, point your
browser at the domain, and it walks through a requirements check, database
connection, and admin account setup. Full walkthrough:
[osclass-classifieds.com/installation](https://osclass-classifieds.com/installation).

## How it's structured

```
oc-admin/       backoffice — folder name is configurable via
                OC_ADMIN_FOLDER in config.php, so it doesn't have to
                stay at the default, predictable path
oc-content/     everything site-specific: uploads, active theme,
                installed plugins, language files, cache
oc-includes/    core PHP classes, DAO layer, bundled libraries
                (PHPMailer, HTML Purifier, TinyMCE, etc.)
```

Core logic and the backoffice are separate from `oc-content`, which is what
makes upgrades non-destructive — you overwrite the core folders and your
themes, plugins, and uploads are untouched.

## Extending it

Customization goes through hooks and filters rather than editing core
files — conceptually close to WordPress, if you've worked with that:

```php
// Hook: run your own code at a defined point
osc_add_hook('item_post_data', 'my_function_after_listing_saved');

// Filter: modify a value as it passes through core
osc_add_filter('item_post_data', 'my_function_before_listing_saved');
```

There are a few hundred hook/filter points across listings, users, search,
email, and structured data — things like `pre_send_mail_filter` (return
`['stop' => true]` to cancel an outgoing email), `structured_data_title_filter`,
or `user_locale_changed`. Themes and plugins live entirely in `oc-content`
and are installed as self-contained folders — no core files need to change
for either.

## Some of what's in core

- **Custom search-rule engine** — define your own permalink patterns
  (`{sCity}/{sCategory}` → `/bremen/for-sale`) with strict or fuzzy param
  matching, prioritized and fully compatible with subdomains.
- **Subdomains** — per-country, per-region, or per-language subdomains,
  with automatic geo-based redirect and optional country-locking.
- **63+ community-maintained language packs**, plus a built-in PO/MO
  editor in the backoffice — translate, merge, or share translations with
  the project without touching files by hand.
- **Structured data on every page** — Schema.org, Open Graph, and Twitter
  card markup generated by core, not left to the theme.
- **Pluggable caching** — Memcache, Memcached, APC/APCU, or Redis.
- **Custom fields** with up to 12 levels of category nesting, and per-field
  types including phone, email, color, number, and URL with correct HTML5
  input types.
